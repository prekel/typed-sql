# Формат кеша запросов

`typed-sql-pgocaml-queries prepare` сохраняет JSON версии **3**. Один файл
описывает роль PostgreSQL, `search_path` и набор запросов. Оба PPX используют
одни логические metadata без OID, credentials и runtime-значений параметров.

```json
{
  "version": 3,
  "role": "app",
  "search_path": "public",
  "types": {
    "pg_catalog.text": {"kind": "scalar"},
    "public.typ123": {"kind": "domain", "base": "pg_catalog.text"}
  },
  "queries": [
    {
      "sql": "SELECT $1::public.typ123",
      "kind": "select",
      "top_level_only": false,
      "parameters": ["public.typ123"],
      "result": [
        {"name": "typ123", "type": "pg_catalog.text", "nullable": true}
      ]
    }
  ]
}
```

## Таблица типов

`types` содержит каждое определение один раз, включая типы, на которые
ссылаются domains и arrays. Ключ — квалифицированное PostgreSQL-имя.
Имена состоят из двух компонентов; компоненты, требующие кавычек, используют
двойные кавычки с удвоением внутренней кавычки. Например, тип `Value` схемы
`app.data` имеет ключ `"app.data"."Value"`, в JSON —
`"\"app.data\".\"Value\""`. Простые компоненты из строчных ASCII-букв,
цифр, `_` и `$`, начинающиеся с буквы или `_`, записываются без кавычек.

Ключи не зависят от порядка запросов или добавления других типов. Одинаковые
имена в разных схемах имеют разные ключи. Ключи записываются в канонической
форме; неоднозначные варианты отклоняются.

Виды определений:

- `scalar`: только `kind`.
- `opaque`: только `kind`; транспортное преобразование выбирает потребитель.
- `enum`: `kind` и `labels` в порядке PostgreSQL.
- `domain`: `kind` и ссылка `base`.
- `array`: `kind` и ссылка `element`.

Определения могут ссылаться вперёд. Reader разрешает каждое определение
один раз и проверяет всю таблицу, включая неиспользованные определения.
Неизвестные ссылки, повторяющиеся ключи, циклы и более 64 вложенных переходов
возвращают ошибки. При построении кеша через API конфликтующие определения
одного PostgreSQL-типа также отклоняются.

## Запросы

`sql` — точный текст после замены OCaml substitutions на `$1`, `$2` и далее.
Пробелы и комментарии входят в ключ. `parameters` — упорядоченные ссылки
на типы. `result` — `null` для команд без строк либо непустой список полей.
Каждое поле содержит `name`, ссылку `type` и boolean `nullable`.

`kind` принимает `select`, `returning`, `command` или `unsupported`.
`top_level_only` сохраняет ограничение вложения запроса. Эти поля проверяются
при чтении и используются compiler при композиции raw queries с DSL.

Типы сообщает PostgreSQL Describe. В примере выше параметр сохраняет domain,
а поле результата имеет базовый тип text. Декодирование выбирается по этим
metadata.

## Размер, порядок и встраивание

Writer сортирует определения по ключам, запросы — по SQL. Порядок параметров,
полей результата и enum labels сохраняется. Отступы отделяют запросы и их
properties; определения типов и поля результата занимают по одной строке.
Общие metadata не повторяются для каждого поля.

Codegen встраивает компактный JSON того же формата. Форматирование файла
не увеличивает встроенный payload. Драйвер читает встроенную строку один раз
при запуске; поиск SQL выполняется через immutable-индекс. При раскрытии
quotations файлы не открываются и подключение к PostgreSQL не создаётся.

Храните JSON и Dune provider в репозитории. После изменения SQL или схемы
повторите `prepare`; `check` сравнивает канонические metadata без записи файла.
