# ADR 0004: простая обработка ошибок выполнения

- Статус: принято
- Дата: 12 октября 2026 года
- Связанные решения: [ADR 0001](0001-static-statement-api.md),
  [ADR 0003](0003-constraint-errors.md)

## Контекст

Эксперимент `experiment/typed-constraint-errors` подтвердил пользу
структурированной диагностики, но добавил четвёртый параметр `Statement.t`,
каталог схемы, вложенные `Left`/`Right` и отдельную программу `Transaction`.
Для обычного обработчика UNIQUE или FK эта сложность не окупается.

Уже существующие адаптеры сообщают категорию нарушения. При классификации
терялись исходные ошибки драйверов, а PG'OCaml не сохранял объектные поля
в публичной диагностике. Ошибка rollback могла скрыть первоначальный сбой.

## Решение

Оставить обычный `Result.t Lwt.t`, прежний `Statement.t` и callback
`transaction ~f`. Добавить backend-independent `Constraint_error.t` с общей
категорией и необязательными полями диагностики, а в оба адаптера — `Error`:

- `constraint_violation` возвращает структурированные сведения;
- `is_constraint_violation` кратко проверяет категорию и заданные имена;
- `cause` возвращает исходную ошибку драйвера;
- `to_string` и `pp` дают человекочитаемую диагностику.

Прикладывать реальные поля PostgreSQL, когда они доступны. Caqti через
общий API не предоставляет имена объектов, поэтому они остаются `None`.
Все фильтры совпадают строго; отсутствующее имя не проходит фильтр имени.
Для повторяющихся имён можно дополнительно указать schema/table. Не
разбирать сообщения и не выводить личность нарушения из списка кандидатов.

В `Constraint_violation` сохранить `cause`. Если rollback завершился
ошибкой после предыдущего сбоя, вернуть `Rollback_failed` с обеими ошибками.
Составной сбой не считается обычной обрабатываемой constraint error.
Cancellation сохраняется как отмена promise.

Не добавлять каталог ограничений, `possible_violations`, типовые эффекты,
кодогенерацию вариантов ошибок, retry policy или новый transaction DSL.
Приложение переводит нужные нарушения в свои ошибки обычным `match`.

## Последствия и проверки

Существующие обработчики `Constraint_violation { kind; _ }` работают без
изменений. Ручное создание такого значения требует нового поля `cause`;
исчерпывающий `match` по adapter error учитывает `Rollback_failed`.

SQLite-регрессии проверяют категории, неизвестные имена, исходную причину и
сохранение ошибок commit/rollback. PostgreSQL-проверки покрывают точное имя
UNIQUE, SQLSTATE и detail, неизвестную личность ошибок, ошибку отложенного FK
на `COMMIT` и cancellation при сбое rollback. Проверки ядра подтверждают
строгость сопоставления и квалификацию повторяющихся имён.

[Руководство с обработчиками](../error_handling.md) показывает прикладной код.
